# Ростелеком Smart Home PRO

**Конкурсный демонстрационный продукт · SIM mode · MAX scope · v1.0.0**

Smart Home PRO — локально запускаемая панель управления умным домом. В комплекте: адаптивный тёмный интерфейс, HTTP API, поток обновлений Server-Sent Events, симулятор устройств, rule engine, журнал событий, энергомониторинг и автоматические тесты.

> Важная граница реализации: камеры, датчики, климат, розетки и охрана представлены виртуальными устройствами. Интерфейс, API, хранение состояния, сценарии и события работают по-настоящему. Видео-поток, распознавание объектов, физические MQTT/RTSP устройства и облачная авторизация не подключены и не должны демонстрироваться как реализованные функции.

## Быстрый запуск

Требуется Node.js 20+ (в проекте нет внешних npm-зависимостей).

```bash
npm start
```

Откройте http://localhost:4173. Данные сохраняются в `data/state.json`. Для чистого демо остановите сервер, удалите этот файл и запустите сервер снова.

## Проверка качества

```bash
npm test
npm run check
```

Тесты покрывают стартовую конфигурацию, валидацию команд, климат, розетки, работу сценариев, охрану и сброс датчиков.

## Демонстрационные сценарии

1. **Ночной свет:** включить правило «Ночной свет» → нажать кнопку симуляции движения через API `POST /api/simulate` с `{"kind":"motion"}` → свет в прихожей станет 65%, в журнале появится действие сценария.
2. **Охрана:** убедиться, что система под охраной → `door_open` → состояние охраны станет `alert`, появится критическое событие. `door_close` сбрасывает датчик двери; режим охраны можно вернуть вручную.
3. **Управление:** изменить яркость, температуру, состояние розетки или охраны в интерфейсе; UI получает новое состояние с сервера.
4. **Энергия:** нажать «Обновить показания» — значения потребления и журнал обновятся.
5. **Режим «Никого нет»:** активировать кнопку в шапке; охрана включается, свет и розетка выключаются.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Проверка доступности |
| GET | `/api/state` | Полный снимок системы |
| GET | `/api/devices` | Список устройств |
| PATCH | `/api/devices/:id` | Изменение значения устройства |
| POST | `/api/simulate` | Симуляция события датчика/энергии |
| PATCH | `/api/rules/:id` | Включение/отключение правила |
| GET | `/api/events` | Журнал событий |
| DELETE | `/api/events` | Очистка журнала |
| GET | `/api/events/stream` | SSE-поток обновлений состояния |

Пример:

```bash
curl -X POST http://localhost:4173/api/simulate \\
  -H 'Content-Type: application/json' \\
  -d '{"kind":"motion"}'
```

## Структура

- `src/domain.js` — доменная модель, валидация команд, симулятор, правила автоматизации.
- `src/server.js` — HTTP API, SSE, раздача frontend, запись состояния.
- `public/` — клиентский интерфейс.
- `tests/` — автоматические тесты доменной логики.
- `docs/` — архитектура, модель данных, безопасность и сценарий защиты.

## Технические решения

- **Local-first:** логика работает локально, интернет не нужен для основного демо.
- **Событийная модель:** команды и датчики создают события; SSE синхронизирует вкладки.
- **Rule engine:** триггер → проверка условий → действие → запись в журнал.
- **Хранение:** JSON-файл с атомарной сериализацией очереди записи; для конкурса это лёгкий вариант без настройки БД.
- **Границы доверия:** API проверяет диапазоны значений и типы команд; тело запроса ограничено 16 КБ.

## Ограничения и следующий этап

Для пилота с оборудованием потребуется добавить адаптеры протоколов (например, MQTT для телеметрии/команд, RTSP/WebRTC для видеопотока), регистрацию и управление устройствами, авторизацию и роли, TLS, аудит безопасности, миграции БД и интеграционные тесты на конкретных моделях устройств. Текущая сборка не является сертифицированной системой физической охраны.
